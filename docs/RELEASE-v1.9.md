## 3. Core Security & Operational Invariants

1. **True Forward Secrecy Guarantee (`sendbeam/3`):**
   - All trusted-device connections derive directional session keys ($k_{i2r}, k_{r2i}$) from an ephemeral X25519 Diffie-Hellman exchange combined with pairwise $k_{pair}$ via HKDF-SHA256 Extract-and-Expand.
   - Private ephemeral scalar buffers are zeroized in memory immediately after shared secret computation.
   - Compromise of long-term identity keys or $k_{pair}$ cannot retroactively decrypt recorded session traffic.

2. **Downgrade & Replay Defense:**
   - Paired devices mandatorily require `sendbeam/3`. Attempts by an attacker or modified peer to downgrade to `sendbeam/2` or `sendbeam/1` fail closed with `ErrProtocolDowngradeForbidden`.
   - Handshake nonces are tracked within a ±5 minute timestamp validity window; replayed nonces abort fail-closed (`ErrSessionReplayDetected`).

3. **Authorized Revocation Hierarchy (ADR 0010):**
   - Self-tombstones are accepted universally fail-closed.
   - Pairwise unpairing drops only direct connections.
   - External contacts have zero authority to issue transitive revocations targeting third-party devices; unauthorized claims are rejected with `ErrRevocationUnauthorized`.

4. **Production Require-Padding Policy:**
   - When `--require-padding` or `require_padding` is configured, connection attempts against peers lacking the padding capability abort fail-closed (`ErrPaddingRequired`).
   - Inbound payload or control frames lacking the `FrameFlagPadded` flag are rejected fail-closed (`ErrUnpaddedFrame`).

5. **Zero-Secret Public DTOs & Diagnostics:**
   - Handshake outcomes, public JSON outputs, and diagnostics redact 64-hex character keys (`<secret>`) and exact unpadded payload sizes (`<redacted>`).
   - Sensitive cryptographic fields are omitted (`json:"-"`) from public data transfer objects.
