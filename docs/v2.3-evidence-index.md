   receiver to `RequirePadding: false` — still passes. The positive path works
   (padded transfer verifies), but nothing demonstrates that a *strict* sender
   is refused by an *incompatible* receiver on the desktop production path.
   `packages/engine/transfer/padding_test.go` and
   `packages/engine/receiver/receiver_test.go` do assert fail-closed at the
   engine layer, so the invariant is implemented; the **desktop** negative case
   is still missing (SB-R07).
2. **No packaged-UI or physical-device evidence.** Everything above is
   service-level or CI-level. Release-gating physical rows remain NOT RUN.
3. **Licensing contradiction is unresolved by design** — see SB-R02 findings; no
   license was changed.
4. Only the desktop engine package was executed repeatedly; other packages were
   exercised once per `just ci-test` leg.
5. Race runs observe schedules, not all schedules. Absence of a report is not a
   proof of absence (see §3-D).

## 5. Harness defect fixed under SB-R03 (PR #289, merged as `bf5f1df5`)

`just ci-test` could never pass at the pre-R03 baseline: the desktop leg of the
`go-test-race` recipe set `CGO_ENABLED=0` while passing `-race`, so it aborted
with `-race requires cgo` before executing any test. CI was never affected
(`ci.yml` runs `go test -race ./internal/...` with cgo enabled). Removing the
override makes the local recipe mirror CI and restores — rather than weakens —
race coverage. Verified after the fix: `just ci-test` → exit 0, 0 data races.

## 6. SB-R02 findings (licensing) — recorded, **not actioned**

Measured with `git grep` over tracked files only (`node_modules` excluded; the
only Apache-2.0 headers in the tree belong to vendored dependencies).

| Fact | Value |
| --- | --- |
| `LICENSE` | **MIT License**, "Copyright (c) 2026 Akshay7273" |
| `package.json` `"license"` | `MIT` |
| Homebrew / Scoop / AUR manifests | MIT-consistent (release metadata for 1.9.0) |
| Files with `SPDX-License-Identifier: AGPL-3.0-only` | **57** — `packages/engine` 33, `apps/cli` 14, `apps/desktop` 10 |
| Files with `SPDX-License-Identifier: MIT` | **0** |
| Tracked Go/TS/Svelte files with **no** SPDX header | **474 of 531** |
| Modules that declare a license in `go.mod` | none |

So the contradiction is broader than "some files say AGPL": the repository
grants MIT at the top level while 57 files — which constitute the shared Go
engine consumed by both the CLI and the desktop app — declare AGPL-3.0-only,
and 474 source files declare nothing at all.

**This is a legal/product decision, not an engineering fix.** Consequences the
owner must decide between include, at minimum:

- **MIT everywhere:** remove the AGPL headers; simplest for downstream use, but
  requires confirming the copyright holder authored that code.
- **AGPL for the engine, MIT for the rest:** splits the distribution model and
  needs explicit per-directory license files plus notice updates.
- **AGPL everywhere:** is compatible with the current top-level MIT grant only
  if the MIT text is replaced, and changes the project's distribution posture
  materially.

No license, header or manifest was modified. Two prefatory steps are
recommended before any change: confirm contributor provenance (that all 57
AGPL-headed files were authored by the copyright holder, so no third-party
grant constrains the choice), and add a machine-checkable SPDX gate so the
inconsistency cannot silently reappear.
